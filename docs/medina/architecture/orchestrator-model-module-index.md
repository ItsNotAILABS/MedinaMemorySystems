## 1. Orchestrator Registry

### ORCH-01 SOVEREIGN_TICK_ORCHESTRATOR
- Responsibility: Beat lifecycle, macro/micro assimilation, law epoch sequencing
- Inputs: Runtime deltas, model outputs, governance state
- Outputs: Accepted state transitions, beat reports

- Responsibility: Cross-plane coupling (memory/governance/model/interface)
- Inputs: Plane state snapshots
- Outputs: Integration consistency verdicts

### ORCH-03 SWARM_CORE_ORCHESTRATOR
- Responsibility: Agent workforce packet routing and arbitration
- Inputs: Task constitutions, agent work packets
- Outputs: Arbitration records, integration contracts

### ORCH-04 FULL_GOVERNANCE_ORCHESTRATOR
- Responsibility: Proposal/approval/policy workflows
- Inputs: Governance proposals, policy sets
- Outputs: Acceptance decisions, compliance traces

### ORCH-05 CONSTITUTIONAL_LAW_ORCHESTRATOR
- Responsibility: RECITAL_PLUS_ONE and no-collapse ontology enforcement
- Inputs: Proposed deltas
- Outputs: Law validation evidence

### ORCH-06 NEURAL_CORE_MESH_ORCHESTRATOR
- Responsibility: Neural mesh coherence and model communication topology
- Inputs: Model route plans
- Outputs: Mesh health, route continuity score

### ORCH-07 LIVING_DOCUMENT_MACRO_ORCHESTRATOR
- Responsibility: D1-D10 lifecycle, chaining, mapping, reinjection
- Inputs: Document organism states
- Outputs: Versioned intelligence packets

### ORCH-08 FRONTEND_COMMAND_ORCHESTRATOR
- Responsibility: Command grammar parse, chat intent routing, UI event parity, F-MODEL coordination
- Inputs: Chat commands, natural language intents, F-MODEL state
- Outputs: Executable action plans and operator feedback
- Controls: All 115 F-MODEL frontend technology intelligence models
- Integration: Maps F-MODELs to U-MODELs for interface composition

## 7. Export Parity Rule

Each orchestrator, model family, and module must expose:
- declaration metadata
- importable API contract
- runtime health endpoint
- invocation count + evidence counters

Missing any export is a parity violation (H1).
