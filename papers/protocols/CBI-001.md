# CBI-001: Code-Block Cognitive Interface

## Chapter 6 of the Sovereign Protocol Canon

**Protocol ID:** CBI-001  
**Version:** 1.0

**Role:** Conceptual Persistence Engine

---

## 1. Definition

Code blocks are **stable cognitive artifacts**: text, JSON, specs, pseudo-code. They represent crystallized thought that persists across reasoning sessions.

## 2. Mechanism

```
Paste Cycle:
1. You paste → engine ingests
2. Artifact becomes node in reasoning graph
3. Re-pasting = re-activating lineage
4. Modification creates new version
5. Promotion marks as canonical
```

## 3. Artifact Structure

```yaml
artifact:
  id: <unique identifier>
  type: <text | json | code | spec | pseudo>
  intent: <purpose of artifact>
  content: <actual content>
  lineage:
    parent: <parent artifact id>
    version: <version number>
    created: <timestamp>
    author: <agent or user>
  status: <draft | active | promoted | archived>
```

## 4. Operations

```
CBI-CREATE: Define artifact with ID, type, intent
  Input: type, intent, content
  Output: artifact_id
  
CBI-LINK: Connect artifacts (dependencies, ancestry)
  Input: source_id, target_id, link_type
  Output: link_id
  
CBI-PROMOTE: Mark as canonical (vault-worthy)
  Input: artifact_id, justification
  Output: promotion_status
  
CBI-VERSION: Create new version
  Input: artifact_id, modifications
  Output: new_artifact_id
  
CBI-ARCHIVE: Move to long-term storage
  Input: artifact_id
  Output: archive_reference
```

## 5. Link Types

| Link Type | Meaning |
|-----------|---------|
| PARENT | Direct lineage |
| DEPENDS | Requires for execution |
| REFERENCES | Cites for context |
| SUPERSEDES | Replaces older version |
| IMPLEMENTS | Realizes a specification |

## 6. Promotion Criteria

An artifact may be promoted when:
- Referenced across ≥N cycles (configurable)
- Verified by AAB-FILTER
- Approved by relevant district
- Attested by NOVA (for canonical status)
