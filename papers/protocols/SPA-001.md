# SPA-001: Self-Programming Architectures

## Chapter 14 of the Sovereign Protocol Canon

**Protocol ID:** SPA-001  
**Version:** 1.0  
**Status:** CANONICAL  
**Role:** Self-Rewriting Organism

---

## 1. Definition

Self-Programming Architectures define how the organism **modifies itself**. Agents can generate tools, refactor code, and update protocols—but only through controlled, verified processes.

## 2. Capabilities

The organism can self-modify:

| Capability | Scope | Guardrails |
|------------|-------|------------|
| Generate tools | Create new utilities | Must pass AAB-FILTER |
| Refactor code | Improve existing code | Must maintain invariants |
| Update protocols | Evolve the rules | Requires NOVA-ATTEST |
| Extend agents | Add new agent types | Must follow AAB-001 |
| Create artifacts | Produce new knowledge | Must follow CBI-001 |

## 3. Guardrails

All self-modifications are guarded:

| Guardrail | Enforcement |
|-----------|-------------|
| NOVA-ATTEST required | For protocol changes |
| Invariant preservation | Automated verification |
| Rollback available | All changes reversible |
| Audit trail | All modifications logged |
| Gradual rollout | Changes staged, not instant |

## 4. Operations

```
SPA-PROPOSE: Propose change
  Input: change_type, change_description, implementation
  Output: proposal_id
  
SPA-VERIFY: Test + simulate
  Input: proposal_id
  Output: verification_result, simulation_report
  
SPA-MERGE: Adopt into civilization
  Input: proposal_id, approvals
  Output: merge_status
  
SPA-ROLLBACK: Revert change
  Input: change_id, reason
  Output: rollback_status
```

## 5. Change Pipeline

```
Self-Modification Pipeline:
1. Agent proposes change (SPA-PROPOSE)
2. Automated tests run
3. Simulation in sandbox
4. AAB-FILTER reviews
5. Verification completes (SPA-VERIFY)
6. Approvals gathered (human/agent)
7. NOVA-ATTEST (if protocol change)
8. Staged rollout begins
9. Monitoring period
10. Full adoption (SPA-MERGE)
```

## 6. Change Categories

| Category | Approval Required | NOVA-ATTEST |
|----------|-------------------|-------------|
| Tool generation | AAB-FILTER | No |
| Code refactor | District approval | No |
| Minor protocol update | Senate majority | No |
| Major protocol update | Senate supermajority | Yes |
| Charter amendment | Federation consensus | Yes |

## 7. Invariants

The following can **never** be self-modified:

| Invariant | Reason |
|-----------|--------|
| Core safety constraints | Existential protection |
| Audit trail requirement | Accountability |
| NOVA-ATTEST for protocols | Trust hierarchy |
| Rollback capability | Recovery assurance |

## 8. Integration

- **AAB-001**: Agents propose and verify
- **CBI-001**: Changes as artifacts
- **NOVA-001**: Attestation for protocols
- **MAE-001**: Multi-agent verification
